## Global Constraints

Every task in every plan implicitly includes this section. Values copied verbatim from `README.md` "Locked decisions" and the recovered decision log.

| Constraint | Value |
|---|---|
| Language | **JavaScript, not TypeScript.** No `.ts` files anywhere in the JS workspaces |
| Module system | **ESM.** Every JS `package.json` carries `"type": "module"` |
| Repo | **Monorepo**, npm workspaces — `client/app`, `client/console`, `server/api`, `server/aiml`, `packages/core` |
| Runtime | **Node 22**, **npm**. `.nvmrc` pins `22` |
| Backend | **Express** + **PostgreSQL 16** + **Prisma** |
| App | **React Native / Expo**, **dev build**, **Android only**, **minSdk 31 (Android 12)** |
| Device DB | **SQLite on the phone, accessed through Prisma** — `@prisma/react-native` + `react-native-quick-sqlite`, a second Prisma schema at `client/app/prisma/schema.prisma`. Migrations ship as bundled SQL applied at app start. **This overrides `SERVER.md` §1's earlier raw-`expo-sqlite` decision** — the user asked for Prisma on both sides. See the caveat block in [plan 02](2026-09-01-02-collector-app.md#device-db-prisma-caveat). |
| Console | **Next.js** (App Router) |
| AI service | **Python 3.13** + **FastAPI** + **uvicorn**. Stdlib maths only — no numpy, no pandas, no sklearn |
| Containers | **None.** No Docker anywhere. Postgres and Python installed natively |
| Languages in app | **Marathi + Hindi.** All strings and all audio ship inside the APK |
| Demo network | **Phone hotspot** — not USB. `adb reverse` survives airplane mode and makes the offline claim unprovable |
| Product name | **Bhaav.** Never "Kabadiwalla Connect" — that is a real Chennai company |
| Registered buyers at demo | **3** console accounts, one per `VALID` seeded recycler. First is Lilashana Sales, Nandra Road, Khamgaon, Dist. Buldhana, Dismantler, 360 MTA |
| Money | `numeric(12,2)` on the server, integer paise or `Decimal` in code. **Never `float`** |
| Quantity | `numeric(10,3)` |
| Timestamps | `timestamptz` everywhere. Device sends ISO-8601 with offset |
| Priority | **Quality over deadline.** Functionality first, then UX for the collector, then cosmetics. Stated verbatim by the user: *"don't think about time, only think about the quality"* |
| AI/ML complexity ceiling | **Rules, not learned models.** Stated verbatim by the user: *"we have less knowledge of AIML so keep it simple but useful"*. `AI.md` §1 and `AI-ANOMALY-SPEC` §0.1 both settle this — the Isolation Forest proposal is rejected |

### Test tooling — decided here so no plan re-litigates it

| Workspace | Runner | Why |
|---|---|---|
| `packages/core` | **Vitest** | pure functions, no environment needed |
| `server/api` | **Vitest** + **supertest** | HTTP-level tests against a real `bhaav_test` Postgres |
| `client/console` | **Vitest** + `@testing-library/react` + `jsdom` for units; **Playwright (chromium)** for end-to-end | the console is a browser product; the two-sided counter-sign is only truly proven in a browser |
| `client/app` | **jest-expo** + `@testing-library/react-native` | Expo requires its own Jest preset for the RN transform; Vitest cannot replace it |
| `server/aiml` | **pytest** | Python |

**Playwright uses chromium only.** Firefox and WebKit are not installed and are not needed — the console targets a desktop or tablet browser at a recycling facility.

**Shared-backend tests run serially.** `server/api` tests all hit one `bhaav_test` database; Vitest is configured with `fileParallelism: false` and every test truncates the tables it touched in `afterEach`. Per `testing-principles`, teardown is by explicit truncation, never by relying on test order.

## Amendments to the spec that these plans make

Four gaps were found while writing these plans. Each is resolved here, and the plan that touches it also updates the authoritative document, so `DB.md` does not drift.

| # | Gap | Resolution | Where |
|---|---|---|---|
| 1 | `handover` cannot record a downgrade. `AI.md` §11 sends `inspected_condition` / `downgrade_reason_code`; `DB.md` §3.7 has neither. D9–D12 are unbuildable without them (`README.md` open item 9, `AI-ANOMALY-SPEC` §0.2) | Add `inspected_condition`, `downgrade_reason_code`, `collector_protest` to `handover` in the **initial** migration, and amend `DB.md` §3.7 in the same task | Plan 01, task 5 |
| 2 | `anomaly_flag.subject_type` CHECK allows only `LOT/HANDOVER/RECYCLER/COLLECTOR`. D13 emits `subject_type: "MARKET"` (`AI-ANOMALY-SPEC` §6.3) and would be rejected | Add `'MARKET'` to the CHECK | Plan 01, task 6 |
| 3 | `AI-ANOMALY-SPEC` gap 9 requires `config_version` on every finding — without it no past decision can be explained. No column carries it | Add `config_version` and `admin_outcome` to `anomaly_flag` | Plan 01, task 5 |
| 4 | `SERVER.md` §5 requires recycler console login; `DB.md` §6 lists no account or session table. `DB.md` §6 explicitly sanctions week-two additions that touch no existing column | Add `recycler_account` and `recycler_session` | Plan 01, task 12 |

One further clarification, made without a schema change:

**The ranking score's staleness term is normalised.** `AI.md` §2 writes `− w4 · rate_staleness_days` with `w4 = 0.05`. Taken literally a 30-day-old rate contributes `−1.5`, which swamps a value term bounded at `+0.55`. All four terms are normalised to `[0,1]`; staleness becomes `min(days / 30, 1)`. The weights are unchanged and still shown in the deck. This is recorded in `packages/core/src/ranking.js` as a comment. (Plan 01, task 4.)

## What is deliberately not built

From `FRONTEND.md` §7 and `DB.md` §6, restated so no task quietly adds one:

User accounts or passwords **for collectors** · UPI or payments · push-notification service · admin dashboard · in-app chat · ratings and reviews · route optimisation · map tiles or a visual map · multi-city onboarding · bidding or auctions · `payment` / `pickup_request` / `message` / `rating` / `notification` / `audit_log` tables · brand or model columns · any device-level taxonomy.

**Detectors D4 and D5 are out of scope** (`AI.md` §10) — blocked on real per-category weight distributions that do not exist (`README.md` open item 7). They stay specified, they skip with a reason at runtime, and the deck says so.

**D14 (evidence photo reuse) is a stretch goal** and is the last task in plan 04. Build it only if everything else is done.
